# Руководство пользователя

Это инструкция по повседневному использованию бота. Про установку и деплой
на сервер/ПК — см. `INSTALL.md`. Про технические детали и архитектуру — см.
`README.md`.

## Что умеет бот

Бот — это секретарь поверх вашего Obsidian-хранилища: вы пишете ему в
Telegram, он ведёт файл задач (`Задачи.md` или другой, указанный в
`.env` → `OBSIDIAN_FILE`) и может сам напоминать о делах по расписанию.
При желании бот также умеет искать по смыслу по всему вашему Obsidian-
хранилищу и находить людей по упоминаниям в заметках, письмах и встречам в
календаре — см. разделы «Second Brain» и «Gmail» ниже.

## Первый запуск

После установки (см. `INSTALL.md`) в `.env` обязательно должен быть заполнен
только один параметр:

```ini
TG_BOT_TOKEN=...   # токен от @BotFather
```

Всё остальное — опционально, бот работает и без этого. Ниже — что каждая
настройка даёт и когда её стоит включить.

### Ограничить доступ только себе (рекомендуется)

Напишите боту [@userinfobot](https://t.me/userinfobot), он пришлёт ваш
Telegram user_id. Впишите его в `.env`:

```ini
ALLOWED_USER_IDS=123456789
```

Без этого параметра бот отвечает всем, кто напишет ему — если бота может
найти кто-то посторонний (например, зная имя бота), лучше сразу ограничить.

### Включить ИИ-классификацию задач

Без ключа бот всё равно работает, но все новые задачи попадают в один общий
раздел «Входящие». Чтобы бот сам раскладывал их по смыслу («Работа»,
«Личное» и т.д.), нужен ключ [DeepSeek](https://platform.deepseek.com/api_keys):

```ini
DEEPSEEK_API_KEY=sk-...
TASK_SECTIONS=Работа,Личное      # можно указать свои разделы через запятую
```

### Включить проактивные сообщения (дайджест, рефлексия, обзор)

Чтобы бот сам писал вам по расписанию (см. ниже), укажите чат и часовой
пояс:

```ini
TELEGRAM_CHAT_ID=123456789   # обычно совпадает с вашим user_id (см. выше)
TIMEZONE=Europe/Moscow
```

Если в `ALLOWED_USER_IDS` указан ровно один ID, `TELEGRAM_CHAT_ID` можно не
задавать отдельно — бот использует тот же ID автоматически.

После любого изменения `.env` бота нужно перезапустить (см. «Проверка и
управление» в `INSTALL.md`).

### Подключить Google Calendar (встречи в дайджесте + подготовка)

Опционально, только чтение — бот не может создавать или менять события.

1. Откройте [Google Cloud Console → Credentials](https://console.cloud.google.com/apis/credentials),
   создайте OAuth-клиент типа **TVs and Limited Input devices**.
2. Там же включите **Google Calendar API** для проекта (если ещё не включён).
3. В терминале на любом компьютере с Python и браузером:
   ```bash
   python scripts/google_calendar_auth.py
   ```
   Введите Client ID и Client Secret из шага 1. Скрипт покажет ссылку и код —
   откройте ссылку в браузере, введите код, разрешите доступ. После
   подтверждения скрипт распечатает три строки для `.env`.
4. Вставьте их в `.env` на машине с ботом и перезапустите бота.

После этого утренний дайджест будет показывать сегодняшние встречи, а бот
сам пришлёт подготовку (тема, время, место, участники + что нашлось по этой
теме в заметках) за `MEETING_BRIEF_LEAD_MINUTES` минут (по умолчанию 30) до
каждой встречи.

### Подключить погоду в дайджест

Опционально, бесплатно, без регистрации ([Open-Meteo](https://open-meteo.com/)).
Нужны только координаты вашего города:

```ini
WEATHER_LATITUDE=55.75
WEATHER_LONGITUDE=37.62
```

Найти свои координаты просто: откройте Google Maps, кликните правой кнопкой
по нужной точке на карте — вверху появятся широта и долгота, кликните по
ним, чтобы скопировать.

После этого утренний дайджест будет показывать погоду на сегодня и
подсказывать взять зонт, если вероятность осадков высокая.

### Подключить Second Brain (семантический поиск, опционально)

Без этого раздела `/search` ищет только по файлу задач (`OBSIDIAN_FILE`),
обычным совпадением подстроки. С настройкой ниже бот индексирует **весь**
ваш Obsidian-vault и ищет по смыслу, а не только по точным словам —
например, запрос «когда я в последний раз обсуждал бюджет» найдёт заметку,
даже если в ней нет слова «бюджет» буквально.

1. Установите [Ollama](https://ollama.com/) — она считает эмбеддинги
   локально, ключ или интернет не нужны. Ollama должна быть запущена (по
   умолчанию — на том же компьютере, что и бот).
2. Скачайте модель для эмбеддингов:
   ```bash
   ollama pull nomic-embed-text
   ```
   (можно и другую модель — тогда укажите её в `OLLAMA_EMBED_MODEL` ниже).
3. Добавьте в `.env`:
   ```ini
   OBSIDIAN_VAULT_PATH=~/ObsidianVault
   ```
   Путь — к папке всего хранилища (не к отдельному файлу задач), и она
   должна уже существовать. `OLLAMA_BASE_URL` и `OLLAMA_EMBED_MODEL` можно
   не указывать — по умолчанию `http://localhost:11434` и
   `nomic-embed-text` соответственно.
4. Перезапустите бота. При старте он сам проверит, что Ollama отвечает, и
   если да — начнёт первую индексацию по расписанию (по умолчанию раз в
   час, `VAULT_REINDEX_INTERVAL_MINUTES`). Чтобы не ждать — отправьте
   `/reindex` в Telegram сразу после настройки.

Если Ollama на момент запуска бота недоступна, Second Brain просто не
включится в этом запуске (бот работает как обычно, без ошибок) — при
следующем перезапуске бот попробует снова.

Без этой настройки всё работает как раньше — ничего не ломается, `/search`
просто продолжает искать только по файлу задач.

### Подключить Gmail (опционально, только чтение)

Бот никогда не отправляет, не удаляет и не меняет вашу почту — только
читает. Даёт: сводку непрочитанных писем в утреннем дайджесте, а также
почту как ещё один источник для `/search` и `/contact` (требует ещё и
Second Brain выше, т.к. поиск по почте использует ту же Ollama).

1. В том же проекте Google Cloud Console, где настраивали Calendar (если
   настраивали — если нет, создайте новый проект), включите **Gmail API**
   и создайте ещё один OAuth-клиент — на этот раз типа **Desktop app**
   (для Calendar был другой тип, «TVs and Limited Input devices»; для
   Gmail он не подходит — Google не разрешает этот scope для устройств с
   ограниченным вводом).
2. Google Cloud Console → OAuth consent screen → переведите статус в
   **«In production»**. Это важно: пока статус «Testing» (по умолчанию),
   refresh token живёт всего 7 дней, и через неделю бот молча перестанет
   читать почту. Для личного использования полная верификация Google не
   нужна — будет только предупреждение «Google hasn't verified this app»
   при первой авторизации, его можно спокойно пропустить («Advanced» →
   «Go to (your app name)»).
3. Запустите на машине с браузером (не обязательно там, где крутится бот):
   ```bash
   python scripts/gmail_auth.py
   ```
   Введите Client ID и Client Secret, когда спросит. Откроется браузер,
   подтвердите доступ — скрипт поймает код авторизации и выведет три
   готовые строки.
4. Добавьте их в `.env`, перезапустите бота:
   ```ini
   GMAIL_CLIENT_ID=...
   GMAIL_CLIENT_SECRET=...
   GMAIL_REFRESH_TOKEN=...
   ```

Почта индексируется локально, отдельно от индекса vault, с хранением
последних **180 дней** (настраивается через `MAIL_INDEX_RETENTION_DAYS`) —
письмо старше этого срока перестаёт находиться через `/search`/`/contact`,
хотя в самом Gmail, конечно, никуда не девается. Переиндексация — по
расписанию (раз в час по умолчанию) или вручную: `/reindex_mail`.

Без этой настройки всё работает как раньше — просто нет раздела почты в
дайджесте и в результатах `/search`/`/contact`.

## Повседневное использование

### Добавить задачу

Просто напишите текст — бот классифицирует его и добавит в файл:

> Закончить презентацию к четвергу

Бот ответит, в какой раздел добавил задачу.

### Спланировать день одним сообщением

```
/plan Позвонить Иванову, закончить презентацию, забрать посылку
```

Бот разобьёт сообщение на отдельные задачи и разложит каждую по разделам.
Если написать `/plan` без текста — бот спросит, что планировать, и возьмёт
ваш следующий ответ.

### Посмотреть список задач

```
/list        — все открытые задачи
/list 10     — только последние 10
```

Если задач много, бот пришлёт список несколькими сообщениями.

### Отметить задачу выполненной

```
/done 3
```

Номер — из последнего `/list`. Бот запишет и время выполнения. Если написать
`/done` без номера — бот спросит номер отдельным сообщением.

### Найти что-то в заметках

```
/search сервер
```

Если настроен Second Brain (см. «Первый запуск» выше) — бот ищет по смыслу
по всему vault, а если ещё и Gmail настроен — заодно и по почте, результаты
из обоих источников перемешиваются по релевантности, не показываются
отдельными списками. Без Second Brain — ищет по обычному совпадению
подстроки, но только в файле задач (`OBSIDIAN_FILE`), почта в этом случае
не участвует. Если написать `/search` без запроса — спросит, что искать.

### Найти человека

```
/contact Иванов
```

Найдёт упоминания имени во всех заметках vault (если настроен Second
Brain), в письмах (если настроен Gmail — по отправителю, теме и тексту
письма) и прошлые встречи с этим человеком из Google Calendar за последние
90 дней (если календарь настроен). Поиск по имени — везде по точному
совпадению подстроки (не морфология: «Иванову» не найдёт «Иванов»), а не
семантический — для имён так надёжнее, и это же позволяет `/contact`
работать даже если Ollama сейчас недоступна.

Если ничего из перечисленного не настроено — бот честно скажет, что искать
негде.

### Обновить индекс vault

Индексация vault для Second Brain идёт сама по расписанию (раз в час по
умолчанию). Если вы только что настроили `OBSIDIAN_VAULT_PATH` или сильно
изменили заметки и не хотите ждать — обновите вручную:

```
/reindex
```

Бот сообщит, сколько заметок добавил/обновил/удалил из индекса. Если
Ollama недоступна прямо сейчас — скажет об этом и ничего не сломает
(индекс останется как был).

### Обновить индекс почты

Аналогично, но для Gmail — своя команда и своё расписание, независимые от
`/reindex`:

```
/reindex_mail
```

Бот сообщит, сколько писем добавил и сколько убрал из индекса по retention
(письма старше `MAIL_INDEX_RETENTION_DAYS`, по умолчанию 180 дней — из
самого Gmail при этом ничего не удаляется, только из локального поискового
индекса).

### Дедлайны

Два способа поставить дедлайн:

**Через команду (рекомендуется):**
```
/deadline 3 2026-09-20
```
Номер — из последнего `/list`. Бот добавит тег `[due:: 2026-09-20]` в текст
задачи (это стандартный формат Dataview/Tasks-plugin).
Убрать: `/deadline 3 off`. Без параметров — бот спросит номер и дату.

**Вручную при добавлении задачи:**
```
Сдать отчёт [due:: 2026-09-20]
```

Дедлайн необязателен — ставьте только там, где реально есть срок. Задачи с
наступившим или просроченным дедлайном помечаются в утреннем дайджесте.

### Приоритеты

```
/priority 3 высокий
/priority 3 2           ← то же самое числом (0-5)
/priority 3 off         ← убрать приоритет
```

Шкала приоритетов (совпадает с офисным задачником):

| Цифра | Уровень |
|-------|---------|
| 0 | FYI |
| 1 | Критический |
| 2 | Высокий |
| 3 | Средний |
| 4 | Низкий |
| 5 | План |

В файле приоритет сохраняется числом — `[priority:: 1]` — а не словом: так
таблица в Dataview сортирует задачи по реальной важности, а не по алфавиту.
Бот сам показывает слово («Критический») в ответах и дайджесте.

Задача с самым высоким приоритетом автоматически становится «главной задачей
дня» в утреннем дайджесте. `FYI` — информационная пометка, никогда не
становится «главной», даже если других задач нет.

### Раздел (категория) задачи

Когда ИИ классифицирует задачу, раздел сохраняется дважды: как заголовок
`## Раздел`, под которым лежит задача в файле, и как тег `[category:: Раздел]`
прямо в тексте задачи — это и позволяет строить таблицу в Dataview (см. ниже).

Если ИИ ошибся с разделом (или классификация выключена), поправьте вручную:
```
/setcategory 3 Маркетинг
/setcategory 3 off       ← убрать раздел
```
Номер — из последнего `/list`. Без параметров — бот спросит номер и раздел.
Команда меняет только тег в тексте задачи, не переносит саму строку между
`## Раздел`-блоками файла.

### Таблица задач в Obsidian (Dataview)

Установите плагин [Dataview](https://github.com/blacksmithgu/obsidian-dataview)
(Settings → Community plugins → Browse → Dataview). Затем создайте в вашем
хранилище отдельную заметку, например `Задачи-таблица.md`, и вставьте:

````markdown
```dataview
TABLE WITHOUT ID
  task.category as "Категория",
  task.text as "Задача",
  choice(task.priority = 0, "FYI",
  choice(task.priority = 1, "Критический",
  choice(task.priority = 2, "Высокий",
  choice(task.priority = 3, "Средний",
  choice(task.priority = 4, "Низкий",
  choice(task.priority = 5, "План", "")))))) as "Приоритет",
  task.due as "Дедлайн"
FROM "ToDo"
FLATTEN file.tasks as task
WHERE !task.completed AND task.text
SORT task.priority ASC, task.due ASC
```
````

Замените `"ToDo"` на путь к файлу или папке с задачами бота (см.
`OBSIDIAN_FILE` в настройках). Таблица обновляется сама при каждом открытии
заметки — бот про неё ничего не знает, он просто пишет теги в обычный
markdown-файл задач.

### Еженедельный обзор

```
/review
```

Покажет, что вы выполнили за последние 7 дней. Так же приходит
автоматически по расписанию (см. ниже).

## Проактивные сообщения (бот пишет сам)

Работают только если настроен `TELEGRAM_CHAT_ID` (см. выше).

- **Утренний дайджест** (по умолчанию 08:00, `MORNING_DIGEST_TIME`) —
  сколько открытых задач, что просрочено, погода на сегодня (если подключена),
  встречи на сегодня (если подключён Google Calendar), непрочитанные письма
  (если подключён Gmail) и какая задача главная. Пробки — в планах, пока не
  подключены.
- **Вечерняя рефлексия** (по умолчанию 21:00, `EVENING_REFLECTION_TIME`) —
  бот присылает список открытых задач и спрашивает, что сделано. Ответьте
  свободным текстом, например:

  > закончил презентацию и позвонил иванову

  Бот сам поймёт, какие задачи из списка вы имели в виду, отметит их
  выполненными и покажет, что осталось «на завтра».
- **Еженедельный обзор** (по умолчанию воскресенье 20:00,
  `WEEKLY_REVIEW_DAY`/`WEEKLY_REVIEW_TIME`) — то же самое, что `/review`, но
  само по расписанию.
- **Подготовка к встрече** (если подключён Google Calendar, за
  `MEETING_BRIEF_LEAD_MINUTES` минут до события, по умолчанию 30) — бот сам
  присылает тему, время, место, участников и что нашлось по этой теме в
  заметках. Приходит один раз на каждую встречу.

## Частые ситуации

**Бот не классифицирует задачи по разделам, всё падает в «Входящие».**
Не задан `DEEPSEEK_API_KEY` — см. раздел выше. Без ключа это ожидаемое
поведение, не ошибка.

**Бот не пишет по утрам/вечерам сам.**
Проверьте, что задан `TELEGRAM_CHAT_ID` (или единственный ID в
`ALLOWED_USER_IDS`) и `TIMEZONE`. После правки `.env` — перезапустите бота.

**Хочу другое время дайджеста/рефлексии/обзора.**
Поменяйте `MORNING_DIGEST_TIME` / `EVENING_REFLECTION_TIME` /
`WEEKLY_REVIEW_DAY` + `WEEKLY_REVIEW_TIME` в `.env` (формат ЧЧ:ММ, день —
`mon`…`sun`) и перезапустите бота.

**В дайджесте не видно встреч / не приходит подготовка к встрече.**
Проверьте, что заданы все три `GOOGLE_CALENDAR_CLIENT_ID/SECRET/REFRESH_TOKEN`
(см. раздел «Подключить Google Calendar» выше) и что событие есть именно в
том календаре, что указан в `GOOGLE_CALENDAR_ID` (по умолчанию — основной).

**В дайджесте не видно погоды.**
Проверьте, что заданы обе переменные `WEATHER_LATITUDE` и `WEATHER_LONGITUDE`
(см. раздел «Подключить погоду» выше) — без одной из них погода не
показывается.

**`/search` не находит то, что точно есть в заметках.**
Если Second Brain настроен — возможно, индекс ещё не успел обновиться
(по умолчанию переиндексация раз в час). Отправьте `/reindex` и попробуйте
снова. Если Second Brain не настроен — `/search` ищет только в файле задач
(`OBSIDIAN_FILE`), а не по всему хранилищу; это ожидаемо, см. раздел
«Подключить Second Brain» выше.

**`/reindex` пишет, что Ollama недоступна.**
Убедитесь, что Ollama запущена (`ollama serve` или приложение Ollama) и
отвечает по адресу из `OLLAMA_BASE_URL` (по умолчанию
`http://localhost:11434`). Если бот запускался, пока Ollama была выключена,
Second Brain не включился для этого запуска — перезапустите бота после
того, как Ollama заработает.

**В дайджесте не видно непрочитанных писем / `/search`/`/contact` не находят
письма.**
Проверьте, что заданы все три `GMAIL_CLIENT_ID/SECRET/REFRESH_TOKEN` (см.
раздел «Подключить Gmail» выше). Для `/search`/`/contact` по почте нужна
ещё и рабочая Ollama (как у Second Brain) — если она недоступна, письма
просто не участвуют в поиске, без ошибки.

**Бот перестал читать календарь/почту через неделю после настройки.**
Скорее всего, OAuth consent screen в Google Cloud Console остался в
статусе «Testing» — тогда refresh token живёт всего 7 дней. Переведите
его в «In production» (не требует верификации Google для личного
использования) и настройте заново через `scripts/google_calendar_auth.py`
или `scripts/gmail_auth.py`.

**Бот вообще не отвечает.**
См. раздел «Если бот не запускается» в `INSTALL.md`.

## Чего пока нет

Пробки в дайджесте (нужен платный API), голосовой ввод в самом боте (если
он вам нужен — используйте внешние инструменты, бот прекрасно работает с
готовым текстом). `/contact` и поиск по почте находят по точному
совпадению подстроки, не по морфологии («Иванову» не найдёт «Иванов») —
для имён это осознанный компромисс, не баг. Gmail — только чтение: бот не
умеет отправлять письма и не будет. Актуальный план развития — в
`NEXT_STEPS.md`.
