# Локальная установка с автозапуском

Инструкция по установке бота на свой ПК так, чтобы он:

- запускался автоматически при загрузке/входе в систему;
- сам перезапускался, если упадёт (сеть моргнула, ошибка, и т.п.).

Это техническая инструкция по установке. Про повседневное использование
бота (команды, проактивные сообщения, настройка ИИ-классификации) — см.
`USER_GUIDE.md` после установки.

Все нужные скрипты лежат в папке `deploy/`:

```
deploy/
  linux/
    install.sh                          - установка + автозапуск (systemd)
    uninstall.sh                        - удаление сервиса
    tg-obsidian-bot.service.template    - шаблон unit-файла (используется install.sh)
  windows/
    install.bat                         - установка + автозапуск (Планировщик заданий)
    start.bat / stop.bat                - ручной запуск/остановка
    uninstall.bat                       - удаление автозапуска
    run_bot.bat                         - обёртка с автоперезапуском (вызывается автоматически)
```

## Linux Mint (и любой дистрибутив с systemd)

### Шаг 1. Склонировать репозиторий

```bash
git clone https://github.com/viktorbrojs-sys/tg_PA_bot.git
cd tg_PA_bot
```

### Шаг 2. Запустить установщик

```bash
chmod +x deploy/linux/*.sh
./deploy/linux/install.sh
```

Скрипт сам:

1. Проверит, что стоит Python 3.12+ (если нет — подскажет команду для установки:
   `sudo apt install python3.12 python3.12-venv`).
2. Создаст виртуальное окружение `.venv` в корне проекта и поставит зависимости.
3. Если `.env` ещё нет — создаст его из `.env.example` и попросит вставить токен
   бота от [@BotFather](https://t.me/BotFather) прямо в терминале.
4. Создаст systemd-сервис `tg-obsidian-bot`, включит автозапуск при загрузке
   системы (`systemctl enable`) и сразу запустит бота.

В процессе установки один раз спросит пароль sudo (нужен, чтобы положить
unit-файл в `/etc/systemd/system/` и управлять systemd).

### Проверка и управление

```bash
sudo systemctl status tg-obsidian-bot     # запущен ли бот
journalctl -u tg-obsidian-bot -f          # логи в реальном времени (Ctrl+C для выхода)
sudo systemctl restart tg-obsidian-bot    # перезапустить вручную (например, после правки .env)
sudo systemctl stop tg-obsidian-bot       # остановить
```

### Обновление кода

```bash
git pull
./deploy/linux/install.sh   # пересоздаст venv/зависимости и перезапустит сервис
```

### Полное удаление

```bash
./deploy/linux/uninstall.sh
```

Удаляет только systemd-сервис. Папку проекта, `.env` и `.venv` можно после
этого удалить вручную (`rm -rf`), если бот больше не нужен.

## Windows

### Шаг 1. Скачать/склонировать проект

Скачайте репозиторий (кнопка **Code → Download ZIP** на GitHub или
`git clone https://github.com/viktorbrojs-sys/tg_PA_bot.git`) и распакуйте
в любую папку, например `C:\tg_PA_bot`.

Убедитесь, что установлен **Python 3.12+** с сайта
[python.org](https://www.python.org/downloads/) — при установке обязательно
включите галочку **«Add python.exe to PATH»**.

### Шаг 2. Запустить установщик

Дважды кликните `deploy\windows\install.bat`
(если появится предупреждение SmartScreen — «Дополнительно» → «Выполнить в любом случае»,
это стандартное поведение Windows для незнакомых `.bat`-файлов).

Скрипт:

1. Проверит наличие Python в PATH.
2. Создаст виртуальное окружение `.venv` и поставит зависимости.
3. Если `.env` ещё нет — скопирует его из `.env.example` и откроет в
   Блокноте, чтобы вы вставили токен бота (`TG_BOT_TOKEN=...`), сохранили
   (Ctrl+S) и закрыли файл.
4. Зарегистрирует задачу **«TelegramObsidianBot»** в Планировщике заданий
   с триггером «при входе в систему» и сразу запустит бота в фоне —
   **без видимого окна консоли**.

Если Windows откажется создавать задачу — запустите `install.bat` от имени
администратора (правая кнопка мыши → «Запуск от имени администратора»).

### Проверка и управление

- Логи бота: `deploy\windows\logs\run_bot.log`
- Остановить бота: `deploy\windows\stop.bat`
- Запустить вручную (если остановили): `deploy\windows\start.bat`
- Убрать автозапуск полностью: `deploy\windows\uninstall.bat`

Автоперезапуск при падении реализован через `run_bot.bat` — он в бесконечном
цикле перезапускает `python main.py`, если процесс завершился (упал или был
закрыт), с паузой 10 секунд между попытками.

> **Важно про автозапуск.** Задача Планировщика создаётся с триггером
> «при входе пользователя в систему» — это самый надёжный вариант, не
> требующий сохранять пароль от учётной записи. Если у Windows включён
> автовход (autologon) или ваш ПК не выключается, а только уходит в
> перезагрузку с последующим автологином, бот запустится сам. Если же вам
> нужен запуск **до** входа пользователя (например, ПК работает как сервер
> без автологина), это возможно только через задачу с сохранённым паролем
> учётной записи (`schtasks /RU имя_пользователя /RP пароль`) или через
> установку как настоящей Windows-службы (например, утилитой
> [NSSM](https://nssm.cc/)) — напишите, если нужен такой вариант, я добавлю
> отдельный скрипт под него.

### Обновление кода

Скачайте новую версию поверх старой папки (или `git pull`), затем снова
запустите `deploy\windows\install.bat` — он переустановит зависимости и
перезапустит задачу.

## Как узнать свой Telegram user_id (для ALLOWED_USER_IDS)

Напишите боту [@userinfobot](https://t.me/userinfobot) — он пришлёт ваш ID.
Впишите его в `.env`:

```ini
ALLOWED_USER_IDS=123456789
```

и перезапустите бота (`sudo systemctl restart tg-obsidian-bot` на Linux или
`deploy\windows\stop.bat` + `start.bat` на Windows).

## Что дальше

Базовая установка не требует ничего, кроме `TG_BOT_TOKEN`. Чтобы включить
ИИ-классификацию задач и проактивные сообщения (утренний дайджест, вечерняя
рефлексия, еженедельный обзор) — см. раздел «Первый запуск» в
`USER_GUIDE.md`, там же — описание всех команд бота.

## Если бот не запускается

1. Проверьте логи (см. выше) — там обычно чётко написана причина
   (неверный токен, недоступный путь к файлу задач и т.д.).
2. Убедитесь, что `TG_BOT_TOKEN` в `.env` заполнен и не содержит лишних
   пробелов/кавычек.
3. Убедитесь, что бот не запущен где-то ещё с тем же токеном — Telegram
   не разрешает две одновременные копии одного бота (ошибка `409 Conflict`).
